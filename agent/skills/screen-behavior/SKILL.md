# Screen behavior skill

Use this when writing Daymeter second-order notes.

## Classification

- browser: chrome, safari, firefox, edge, arc, …
- chat: grok, chatgpt, claude, discord, slack, …
- social: whatsapp, instagram, twitter, youtube, …
- food: swiggy, zomato, …
- system: launcher, finder, settings, phonemanager, …
- other: everything else

Package ids count (`com.whatsapp` → social).

## Stretch math

Computer looks without `seconds`/`end`: gap to next look on **that device**, min 1 min, cap 20 min, tail +5 min. Say “estimated”.

Phone/computer rows with `seconds` or `end`: timed. Do not cap.

## Dual machine

Same ISO second, Mac + MSI → split attention (different apps) or duplicate (same app).  
Half-hour overlap → “both awake” slice, not a collaboration score.  
Hop → consecutive computer looks on different devices, ignore <2s (that is the same-second pair).

## Waste vs work

You do not know intent. Chrome at 22:44 might be work. Instagram in a 8-second jump loop is a cheap loop. Separate those.

High jumps/hr is the strongest waste proxy in this product. Dual lids at the same second is the next. App name alone is not.

## Recovery is already in the log

Prefer pointing at a look that **stopped** (Mac after 21:51:54) over inventing a plan. Improvement is what to change in collectors or habit so the next log is cleaner.

## Evidence lines

Every note should be falsifiable from the looks log. If you cannot list clocks, do not publish the note.
